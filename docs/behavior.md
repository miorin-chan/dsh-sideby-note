# 行为规则

本文是边记部用户可见行为规则与不变量的唯一来源，回答「什么样算对」。
改行为时先更新本行为契约，再改实现与测试。契约不依赖测试名、函数名或文件名。
实现结构见[架构](architecture.md)，界面约束见[面板 UI 规则](panel-ui-rules.md)，验证方式见[测试工程](testing.md)。

## 维护约定

规则用业务语言描述用户可观察的结果。「边界」包含正常路径及其临界情形，「拒绝」记录不应接受的输入或不应发生的结果，
「违反时」说明没有守住规则会给用户带来什么后果。
没有对应情形时省略该行。讨论变更时先看后果是否需要避免，再核对预期行为及其边界。

从契约推导测试，不从现有断言反推契约。输入约束按等价类与边界值挑选场景，多条件组合用决策表梳理，
生命周期沿状态迁移核对，依赖异常用故障注入，并发场景检查交错顺序和跨操作的不变量。
失败时除了核对提示，还要检查哪些输入、记录或状态应保留。
仅重构实现不改变契约，行为变更则说明理由和受影响的分支。

## 便笺内容与生命周期

- **文本长度与空白**：便笺文本去除首尾空白后必须非空；超过 280 字符的部分被截断，而不是拒绝写入。\
  边界：1–280 字符的非空文本被完整保存。280 字符完整保留，281 字符起被截断到 280。\
  拒绝：空或纯空白文本不产生任何记录。\
  违反时：空白便笺变成点不掉的空行；超长粘贴被整条拒绝，用户以为没记上。

- **录入与恢复附件**：宿主存储可用时，便笺可通过选择、粘贴或拖放附上文件；草稿恢复与退回应保留附件。\
  边界：附件单独成条，图片、音频和视频可预览，附件可下载、移除与退回。\
  拒绝：空文件被拒绝，上传失败时已有草稿保留。\
  违反时：用户以为已留存的媒体在关面板、提交或退回后丢失。

- **从会话输入框保存草稿**：从会话输入框发来的纯文本草稿保存为待续便笺，保存成功后清理原草稿。\
  边界：280 字符以内的文本保存到当前工作区，保存成功后清空原草稿。保存期间编辑草稿时保留新内容，连点仍只创建一条便笺；引用和首尾格式保留在原输入框。\
  拒绝：带附件、超长或写入失败时保留完整草稿，不新增便笺。\
  违反时：保存失败或响应迟到时，会话草稿及后续编辑可能丢失。

- **会话绑定**：新便笺默认绑定当前会话且可解绑，绑定或解绑不改变便笺的工作区归属或可见范围，退回编辑保留原绑定状态。\
  边界：绑定、解绑和重开都保留原工作区，正文与附件不受影响。没有绑定的旧条目和草稿读作未绑定，旧会话清单迁移不推断关系。\
  拒绝：空值或无效的绑定输入不产生绑定。\
  违反时：旧便笺被意外绑定，或编辑、刷新后找不到要继续的会话。

- **填入绑定会话**：绑定便笺只可填入绑定会话。打开会话与填入分开，打不开时可以保留便笺或解绑。\
  边界：打开目标不写草稿，明确填入后才写入目标并归档；未绑定的便笺照常填入当前会话。\
  拒绝：目标缺失、处于其他会话或绑定在填入前改变时，草稿和归档状态保持不变。\
  违反时：正文或附件被写进错误的对话，或便笺在未写入时被归档。

- **清单顺序**：新便笺加入所属工作区的待续区首位。待续便笺支持键盘和拖动重排，归档便笺在各显示分组内按归档时间倒序。\
  边界：新便笺排在所属工作区的最前，待续区记住所排顺序，每组最新归档排在组首。\
  违反时：新便笺沉到底部、刚完成的找不到，用户重复记录同一件事。

- **相对时间分档**：便笺的时间文案按经过时长分档：不足 1 分钟显示「刚刚」，不足 1 小时按分钟，不足 24 小时按小时，不足 7 天按天，再早显示日期。\
  边界：各分档显示对应文案。59 秒仍是「刚刚」，60 秒起按分钟；23/24 小时、6/7 天同样在边界切换。\
  违反时：刚记的便笺显示成「8 天前」，或旧便笺永远显示「刚刚」，用户无法判断新鲜度。

- **归档、退回与空态**：递入会话成功后归档并记录时间；退回把便笺移入顶部输入框，用户可以续写后重新提交；无便笺时显示空状态。\
  边界：递入成功后归档；退回到空输入框后移除原记录，重新提交后计为待续。退回后可修改再提交，也可丢弃顶部草稿。\
  拒绝：已有顶部草稿时禁止退回，保留原条目及草稿。\
  违反时：原便笺与退回草稿同时存在会产生重复；现有草稿被覆盖会丢失内容。

- **清除确认**：清除已完成属于破坏性操作，必须二次确认；确认窗口 5 秒内未操作则自动失效。\
  边界：5 秒内二次确认才删除。\
  拒绝：只点一次不删除；超过 5 秒后再点需要重新确认。\
  违反时：一次误点清空全部已完成事项，且没有撤销入口。

- **便笺持久化**：新增/修改/删除成功后立即持久化，刷新页面仍在；写入失败时界面不得假装成功。\
  边界：成功后重开面板或刷新仍是同一份数据。\
  拒绝：写入失败保留原样并明确提示。\
  违反时：关掉面板或刷新后便笺消失；失败时界面仍显示“已保存”。

## 清单范围与归属

- **默认范围与清单汇总**：有工作区绑定时默认展示工作区清单。全局汇总各工作区及未归属便笺，待续与归档优先显示当前工作区。范围选择会记住。\
  边界：全局显示各工作区条目且当前工作区在前，工作区仅显示当前工作区，标题栏分别显示对应范围的待续数。有工作区绑定的空白会话遵循已保存的全局选择。\
  违反时：工作区筛选显示其他工作区的条目，全局漏掉条目或未优先显示当前工作区，或标题栏计入已归档的便笺。

- **首轮前后的入口与范围**：空白新会话可正常记录便笺。首轮对话后入口移入会话工具行，筛选保持原样。\
  边界：首轮前可切换可用的筛选并新增便笺。首轮对话后面板保持打开，入口移动，筛选和写入归属保持原样。\
  违反时：首轮前无法使用面板，或首轮后切换了筛选或丢失已写便笺。

- **独立会话的范围**：无工作区绑定时仅提供全局范围，新增便笺存于保留的未归属清单。\
  边界：显示全局范围，新增条目落在未归属清单。空白新会话没有工作区时也能使用全局范围。\
  违反时：无工作区时无法记录便笺，或内容被写入旧会话清单或任一真实工作区。

- **旧会话便笺迁移**：按工作区归属迁移旧会话便笺，成功后移除源记录；曾经并入过的会话仍需迁移不同 ID 的条目。\
  边界：每个工作区保留各自的全部旧便笺，成功后删除源记录。已并入过的会话只补入不同 ID 的条目，重复打开不产生重复记录。\
  违反时：旧便笺丢失、被重复并入，或因旧会话副本再次出现而复活。

- **新增便笺的归属**：新增便笺始终写入当前工作区；无工作区绑定时写入未归属清单。筛选只决定显示内容。\
  边界：全局与工作区下新增的便笺均写入当前工作区。\
  拒绝：只切换筛选时便笺存储无变化，输入内容仍在草稿中。\
  违反时：全局下新增写到了另一工作区，或切换筛选改动了便笺。

- **全局操作的写入归属**：全局下的归档和退回操作按便笺原有归属写入，退回后重新提交仍回到原清单。\
  边界：归档、退回和重新提交都更新原工作区。两个工作区有相同原始 ID 时仍只更新被操作的那一条。\
  违反时：相同 ID 的另一工作区便笺被改动，或退回后的便笺写到错误的工作区。

## 存储、草稿与并发

- **存储格式兼容**：未切换时浏览器回退数据保持既有 v1 结构；切换后宿主数据使用 aside_note 领域（sessions/workspaces/forwarded + global）；升级不把旧键改写成另一套结构，也不改写宿主文件格式。\
  边界：未切换时浏览器旧数据原样可读、可写。切换后宿主文件沿用 aside_note v1 领域结构。\
  违反时：升级后旧浏览器数据读不出来，或切换前后的结构互相覆盖，用户在两处看到不同便笺。

- **宿主便笺与浏览器状态**：切换后便笺的唯一数据源是 DSH 宿主的本地文件；设备状态（面板宽高、分区、顶部草稿）仍留在浏览器。\
  边界：宿主可用时便笺只读写宿主文件，设备状态仍按浏览器保存。\
  拒绝：切换后仍把便笺写进浏览器键，或把设备状态写进宿主文件。宿主文件已被另一个插件占用时写入浏览器便笺键，导致两处数据分叉。\
  违反时：换浏览器或清站点数据后便笺丢失；或同一份便笺在文件和浏览器里各写一份，恢复后出现两份真相。

- **附件鉴权与存放**：宿主校验上传和读取请求的权限。附件以内容哈希去重，在实际 JSON 便笺存储旁完整发布；便笺保存附件元数据。\
  边界：经鉴权的上传与重试返回同一内容哈希；读取以下载形式返回原始字节。宿主接收 1 字节到 25 MiB 的附件，一条便笺可引用最多 10 个附件。\
  拒绝：拒绝未授权请求、空文件、超限文件与无效哈希；空正文需至少一个有效附件。\
  违反时：其他网页可以访问附件，或下载到半个文件；附件和便笺分开迁移后，便笺遗失其内容。

- **首次探测与切换**：升级后首次启动探测宿主存储：可用时把浏览器旧数据迁移一次并写一次性模式标记，之后单向使用宿主；不可用时不切换、保留浏览器数据、提示并在下次启动重试；迁移中断后重启应补完且不重复。\
  边界：宿主可用且为空——迁移旧数据并写标记。宿主可用且已有数据——不迁移，保留浏览器副本并提示。迁移中断后重启——补完未完成迁移，且不重复写入。\
  拒绝：宿主不可用却写标记、清空浏览器数据或假装已切换。\
  违反时：每次启动重复迁移产生重复条目；或不可用时假装切换，用户新写的便笺留在浏览器而宿主恢复后看不到。

- **宿主不可用**：已切换后宿主不可用（路由缺失、文件打不开、网络失败）时，面板进入错误态并停止写入，不得改回浏览器存储；未切换时宿主不可用则继续使用浏览器存储并提示。\
  边界：未切换 + 宿主不可用——继续用浏览器存储，提示原因，不写标记。\
  拒绝：已切换 + 宿主不可用——写入浏览器或静默回退展示浏览器数据。\
  违反时：宿主故障时偷偷写浏览器，恢复后两份数据分叉；或已切换后仍展示浏览器旧数据，用户误以为宿主便笺丢了。

- **宿主原子合并**：宿主模式写入只提交本页新增、修改与删除的条目，由宿主在最新记录上按 key 串行原子合并；另一标签页新增的条目不得被整条记录覆盖。\
  边界：两端新增都保留；同一条目冲突取较新的修改。\
  拒绝：用整条记录覆盖宿主最新记录，丢掉另一侧新增。\
  违反时：两个标签页同时编辑，后写的一侧把另一侧刚记的条目整条覆盖，用户丢便笺。

- **损坏数据处理**：浏览器回退数据无法解析时，原始内容必须先原样备份，再按空清单继续；宿主文件无法打开时不得静默重建、不得改回浏览器写入，必须报错并停止写入。\
  边界：浏览器坏数据备份到 `<键>.corrupt` 后继续，面板仍可用。\
  拒绝：宿主文件打不开却自动重建，或静默改用浏览器数据。\
  违反时：一次坏数据导致便笺被静默清空；或宿主文件损坏时自动重建/切回浏览器，把用户带到错误的空状态。

- **畸形记录清洗**：存储里的单条记录字段不合法时按缺失处理：非对象、空文本或重复 id 的条目被丢弃或修正，不渲染乱码，也不让面板崩溃。\
  边界：合法条目原样保留。\
  拒绝：非对象被丢弃、空文本被丢弃、重复 id 被重新分配、非法时间戳被修正。\
  违反时：手改或旧版本留下的脏条目让列表显示 undefined，或一次坏条目把整份清单带崩。

- **并发写入合并**：写入前必须基于最新记录合并：浏览器回退路径读回最新记录按 id 合并；宿主路径只提交变更条目，由宿主原子合并。不得整份覆盖另一标签页的写入；同一条目冲突取较新的修改；本页删除的条目不得被并发写入复活。\
  边界：两端新增都保留；冲突取新；本页删除保持删除。\
  违反时：两个标签页各记一条，最后只剩一条（另一条被整份覆盖）。

- **跨标签页刷新**：其他标签页写入后，本页已打开的入口与面板必须自行刷新：浏览器回退用 storage 事件，宿主模式用 BroadcastChannel；不需要用户手动重开。\
  边界：另一标签页新增/删除后，本页角标与列表跟随。\
  违反时：另一标签页删了，本页还显示；再操作就把已删条目写回去。

- **读取失败**：存储读不到时：未切换的浏览器回退按空清单继续，面板仍能打开；已切换的宿主模式进入错误态并停止写入，不得改为读取浏览器旧数据。\
  边界：未切换 + 读不到——按空清单继续，面板可用。\
  拒绝：已切换 + 读不到——回退展示浏览器旧数据或继续写入。\
  违反时：一次存储不可读就让面板打不开，用户连新便笺都记不了；或已切换后把浏览器旧数据当成宿主便笺展示。

- **写入失败**：写入失败时（浏览器配额/磁盘/权限，宿主路由拒绝、超时或文件不可写），读取照常显示已保存内容，界面保留输入并明确提示，不产生幽灵条目；宿主模式不得把失败写入改存到浏览器。\
  边界：可写时正常保存。\
  拒绝：写不进时（配额、磁盘、只读、宿主失败）读取不受影响，输入保留、提示明确、不出现幽灵条目。\
  违反时：用户以为记下了实际没落盘；或写失败后连原本已保存的便笺也看不见了。

- **清单容量**：清单条数不设上限；条目很多时仍能展示、新增和删除，不因条数被拒绝。\
  边界：常规条目数下读写正常。数百条时仍可展示、新增与删除。\
  违反时：条目多的用户在新增时被静默丢弃，或面板因为条数太多而卡死。

## 未提交草稿

- **草稿归属与消费**：草稿属于工作区而不是单个会话；切换会话或在两种范围间切换，半截文字都不丢。\
  边界：同一工作区的任一会话都能看到同一份草稿。\
  拒绝：提交后草稿被消费，不残留。\
  违反时：切个会话半截文字就没了，用户得重打一遍。

- **旧草稿迁移**：升级前按会话保存的草稿，首次打开工作区时并入共享键，旧副本退役，不重复并入。\
  边界：旧草稿并入并可继续编辑。\
  拒绝：旧副本不再出现。\
  违反时：升级后旧草稿再也不出现；或同一份旧草稿被重复并入。

## 递入会话

- **递入目标**：转发只写入当前可见会话的输入框，不得写进其他会话。\
  边界：目标会话出现该条目，其他会话输入框不变。\
  违反时：便笺被转发进另一个会话的输入框，用户发错内容。

- **追加便笺原文**：递入时追加便笺原文，保持现有会话草稿。仅在需要分隔时补一个换行，不加提示语或列表标记。\
  边界：空输入框直接写入原文；非空输入框追加便笺原文。尾部已有换行时直接追加，不产生额外空行。\
  违反时：会话草稿被覆盖，或便笺被拼接到正文同一行、被前缀改写。

- **递入原始附件**：填入时把所有附件按保存顺序带进当前会话草稿，原文件名和内容随附件一起保留。\
  边界：混合便笺和纯附件便笺都可填入，原有草稿与附件保留。\
  拒绝：原文件读取失败、输入框拒收或会话切换时，便笺保持待续。\
  违反时：用户以为多媒体已进入对话，实际只带进正文或部分文件。

- **递入后归档**：递入成功后归档所属清单中的便笺；归档条目不再提供递入操作。\
  边界：成功后在原清单归档并移除递入操作。\
  拒绝：会话输入框不可用时保持原条目待续。\
  违反时：递入失败后便笺消失，或已归档便笺可再次递入造成重复。

## 入口与面板

- **入口与角标**：入口出现在会话工具行；空白新会话没有工具行时出现在右上角。点击入口打开面板。角标显示所在工作区的待续数，独立会话显示全局待续数。\
  边界：两种会话状态下入口位置与计数都正确。\
  违反时：找不到入口、角标随面板筛选改变，或尚未读到数据时显示待续数量。

- **点外收起**：点击面板外部时收起面板，保留点击目标的操作、焦点和边记部草稿。\
  边界：点击外部目标时面板收起，重开时恢复草稿。\
  拒绝：点击面板或其预览时不收起，从面板内开始的手势也不当成外部点击。\
  违反时：外部点击后面板仍打开、挡住目标操作或抢回焦点，或面板内交互误关面板。

- **快捷键切换**：会话工具行的入口可用时，DSH 快捷键可打开或收起面板，入口提示随有效键位更新。\
  边界：命令通过当前会话的入口打开或收起面板，入口随目录更新显示有效绑定。\
  拒绝：对话框占用输入、入口不可见或已解绑时，快捷键不作用于面板。\
  违反时：键盘无法切换面板，或提示仍显示已经换掉的绑定。

- **面板尺寸**：面板宽度限制在 280–720 之间且不超过视口可用宽度，高度不小于 240 且不超过视口可用高度；通过左下角把手拖动或键盘方向键同步调整并记住，双击或按 `Home` 复位。\
  边界：调整并持久化；越过上下限时夹住，不出现溢出。\
  违反时：面板宽或高超出屏幕，或窄到内容不可读。

- **保存警告**：正常面板底部不显示「存储」折叠按钮或说明；写入失败时在面板底部直接显示保存警告。\
  边界：写入正常时无页脚区域；写入失败时底部展示当前存储对应的错误提示。\
  违反时：正常界面多余占用底部空间，或写入失败时缺少警告提示。

- **无使用统计**：边记部不发送匿名使用数据，不提供统计开关。\
  边界：打开面板与切换状态时不发送使用数据。\
  拒绝：任何匿名使用数据上报或统计开关都违反约定。\
  违反时：操作触发后台上报，隐私承诺失效。

- **分区折叠记忆**：未完成/已完成分区的折叠状态被记住，重开面板保持。\
  边界：折叠后重开仍是折叠。\
  违反时：每次打开都要重新折叠已完成区。

## 面板文案与隐私披露

- **面板文案**：面板标题、输入占位、左下角调整大小标签及各操作文案均使用当前语言。\
  边界：界面文案全部来自词典且随语言即时切换。\
  违反时：界面出现未翻译键名或混入另一种语言的文案。

## 语言与文案

- **即时切换语言**：切换 DSH 语言后已打开的边记部面板即时更新界面文案，递入的便笺仍保留原文。\
  边界：中文与英文面板分别显示产品译名；递入内容保持原文。\
  违反时：切换语言后面板滞留旧语言，或递入时给用户文本添加了提示语。

- **语言回落**：未知语言或缺键时回落到英文，绝不回落到中文，也绝不把 key 直接显示给用户。\
  边界：未知语言显示英文。\
  拒绝：显示 key 或中文属于缺陷。\
  违反时：未知语言时界面显示 popover.title 这样的 key，或突然变成中文。

## 产物与卸载

- **插件加载**：产物能在 DSH 中加载并注册会话捕获、空白会话座位与全局 Toast 三个座位，携带 DSH 的八种官方语言。\
  边界：加载后三个座位与八种语言都在。\
  违反时：插件加载失败，面板不出现或页面出现加载错误。

- **卸载清理**：卸载后注入的样式被移除，页面不残留插件痕迹。\
  边界：卸载后样式归零。\
  违反时：卸载后残留样式，其他插件的布局被影响。

## 不变量

- **数据不得静默丢失**：用户已经写下的便笺，不会因为数据损坏、并发写入或存储失败而静默消失。\
  约束：损坏数据处理、并发写入合并、读取失败、写入失败、便笺持久化。

- **操作不得串范围**：工作区筛选只展示当前归属的便笺；全局跨工作区展示，写入按便笺归属，递入只更新当前对话。\
  约束：默认范围与清单汇总、新增便笺的归属、全局操作的写入归属、递入目标、跨标签页刷新。

- **重复操作不增副本**：同一条目最多存在一份有效记录；重复并入、重复写入不产生重复。\
  约束：旧会话便笺迁移、并发写入合并。

- **不报告虚假成功**：失败必须可见：写失败、加载失败都要明确告知，不得报告成功。\
  约束：写入失败、插件加载。
