# 测试工程

本文件说明代码测试如何组织、运行和作为合入门禁。
用户可见的预期行为与不变量见 [行为规则](behavior.md)。

## 结构

Node 在 `engines.node` 支持的版本上直接执行 `.mts` 测试源码。
`npm test` 先构建 Host、Client 和安装器，再用 `node --test "tests/*.test.mts"` 运行全部测试。

| 文件或目录 | 职责 |
| --- | --- |
| `tests/contract.test.mts` | 读取源码、配置、样式和产物，检查打包约定、宿主与浏览器边界、字典及界面约束 |
| `tests/bundle.test.mts` | 在 jsdom 启动构建产物，验证加载、入口、面板主流程、工作区清单与浏览器存储 |
| `tests/resilience.test.mts` | 验证读写故障、跨标签页刷新、迁移重试、大清单、确认时限和宽度边界 |
| `tests/forward.test.mts` | 验证递入的目标、原文与附件顺序、宿主拒收、回滚和交错操作 |
| `tests/draft-uploads.test.mts` | 验证草稿上传限额、异步完成与取消、失败重试及引用恢复 |
| `tests/host-store.test.mts` | 验证宿主存储格式、路由校验、迁移、原子合并、偏好与路径 |
| `tests/host-bundle.test.mts` | 用假宿主端点驱动构建产物，验证切换、不可用和重连、存储详情及面板附件 |
| `tests/host-attachments.test.mts` | 验证宿主附件的鉴权、按内容去重、原件读写、有效引用与清理 |
| `tests/linked-session-bundle.test.mts` | 验证面板绑定与解绑、退回后保留绑定、返回目标及只在目标会话填入 |
| `tests/linked-session-storage.test.mts` | 验证会话绑定在浏览器与宿主模式下的读写和旧记录兼容 |
| `tests/locale-reload.test.mts` | 验证语言服务更换后译文和语言标识随之更新 |
| `tests/resize-cleanup.test.mts` | 验证拖拽取消、失焦与卸载时清理尺寸交互、页面样式和观察器 |
| `tests/install.test.mts` | 在临时 profile 验证安装器的备份、旧包替换、幂等、预演与错误提示 |
| `tests/screenshot-notes.test.mts` | 核对截图 SOP 与脚本使用的演示便笺及时间，并验证脚本可在独立环境执行 |
| `tests/testkit/` | 提供 jsdom 产物启动器和插槽装置，可注入存储故障、计时与语言状态 |
| `tests/fake-store.mts` | 提供内存存储领域、宿主上下文和请求鉴权替身 |

## 命令

| 命令 | 用途 |
| --- | --- |
| `npm test` | 构建并运行全部代码测试 |
| `npm run check` | 先编译构建脚本，再依次运行类型检查、构建与测试、构建产物校验和 DSH 类型钉住校验 |
| `npm run typecheck` | 检查 Client、Host、安装器、构建脚本和截图工具的类型，不生成文件 |
| `npm run build` | 生成构建脚本、Host、Client 和可执行安装器 |

## 约定

- 改变行为时先更新 [行为规则](behavior.md)，再补验证该行为的测试。
  测试名描述用户可见的结果。
- 有效分支与适用的拒绝、边界分支成对检查。
  失败除了检查提示或错误，还要检查草稿、清单、归属等状态未被误改。
  缺陷的复现保留为回归测试。
- 契约测试读源码，断言必须维持的约束。集成测试在 jsdom 中启动构建产物并驱动交互。
  宿主测试通过内存 fake store 或假端点模拟 DSH，安装器测试使用临时 profile。
- 测试不联网，不依赖真实 DSH 安装。
  测试失败时先查明原因，不跳过测试或放宽断言来掩盖问题。

## 有效性证据

2026-11-18 的变异测试逐次向实现注入一个缺陷，重建并运行测试，再还原源码。
首轮检出 9/13，暴露了「存储侧超长文本」未测试和「假时钟掩盖确认窗口常量」两个盲区，补测后检出全部 13/13。

该次检出的缺陷涉及文本截断、损坏备份、并发合并、读失败、写失败、确认窗口、空白会话、
语言前缀、更新说明对草稿与预发布的筛选、容量、宽度、时间分档和记录清洗。
便笺附件由现行代码测试覆盖，不在当时的变异范围内。

这次检查针对浏览器回退与界面的关键路径，未对宿主迁移、宿主原子合并或宿主不可用错误态注入变异。
配套脚本已移除，结论仅作为一次性历史证据，不是持续门禁。

## CI 门禁

[CI 工作流](../.github/workflows/ci.yml)在推送到 `main` 和拉取请求时运行，使用 Ubuntu 与 Node 22、24 矩阵。
各检查按下列顺序执行。

1. 用 `pnpm install --frozen-lockfile` 安装依赖并构建产物。
2. 连续两次 `npm pack` 比较打包结果，确认 Git 不追踪生成的 JavaScript，并检查包内应有的运行文件、
   安装器可执行权限与 shebang，以及不含 `.mts` 源码。
3. 用 `npm run typecheck` 检查类型。
4. 用 `node scripts/build.mjs --check` 校验构建产物，用 `node scripts/sync-types.mjs --check` 校验 DSH 类型钉住。
   CI 未设置 `DSH_INSTALL_DIR` 时跳过类型版本比对。
5. 用 `npm test` 重建并运行全部代码测试。

## 已知边界

- 浏览器配额耗尽、磁盘满和 profile 只读通过 jsdom 注入，未在真机重现。
  真机验收见 [本机实装与验收 SOP](auto-test-sop.md)。
- 400 条清单已验证可展示与新增，未测量滚动或渲染性能。
- 面板高度下限 240 px 与用键盘调整高度尚无测试。
- 多个 DSH 进程共用 `$DSH_HOME` 时没有跨进程写锁，测试未覆盖这一场景。
- 变异测试只提供一次性历史证据，不代表现行覆盖完整，也不会随 CI 重跑。
